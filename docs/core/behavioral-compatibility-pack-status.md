## Upstream Baseline

The current upstream `neo4j-labs/agent-memory-tck` repository describes a formal Technology Compatibility Kit with 189 executable scenarios, stable `SCN-*` scenario IDs, Bronze/Silver/Gold/Platinum tiers, and an HTTP bridge protocol for cross-language conformance. This pack keeps local .NET evidence in two forms:

- mirrored in-process integration scenarios for behavior we can prove directly against the .NET services;
- bridge-readiness documentation and command/task entry points for running the upstream TCK when a bridge adapter is available.

Ran the real upstream Technology Compatibility Kit against the live .NET bridge — `pytest -m bronze --bridge-url http://localhost:3001` against `neo4j-labs/agent-memory-tck` @ commit `4603b91f` (main), driving `tools/AgentMemory.TckBridge` over HTTP against a live Neo4j 5.26 (Docker). **Result: 93 passed, 0 failed** (96 deselected = the Silver/Gold/Platinum scenarios). **Bridge now serves 12 endpoints (was 9):** the 9 Bronze short-term endpoints (`setup`, `teardown`, `clear_all_data`, `add_message`, `get_conversation`, `search_messages`, `list_sessions`, `delete_message`, `clear_session`) plus 3 Bronze schema-tier long-term create endpoints (`add_entity`, `add_preference`, `add_fact`). The TCK `bronze` marker is defined as "schema and short-term memory", so full Bronze conformance requires the long-term create endpoints (their schema tests assert the round-tripped shape of created entities/facts/preferences). Long-term records are embedded via the deterministic `StubEmbeddingGenerator` and default `Confidence` to 1.0.

**Five real defects found and fixed.** These surfaced only because the upstream runner uses its *own* Pydantic models on both ends of every call — unlike the in-process mirror tests, which used the bridge's own DTOs and so could not catch a contract mismatch:

1. **`TckSessionInfo` shape was wrong.** The bridge emitted `{session_id, conversation_count, message_count, last_message_preview, last_activity}`, but the TCK `TCKSessionInfo` model requires `{session_id, message_count, created_at, updated_at}` and reads `created_at` as a required key. Corrected the DTO + mapping. (This overturns the earlier "superset is safe" guess.)
2. **Invalid Cypher in the vector-index readiness poll.** `SHOW INDEXES WHERE ... RETURN count(*)` (missing a `YIELD`) is a Neo4j 5.x syntax error; the `catch` swallowed it, so the poll silently burned its *full* timeout on every call (30s in the bridge `/setup`, 60s in the test fixture). This existed in BOTH the bridge and the repo's `Neo4jIntegrationFixture.WaitForVectorIndexesAsync` (a genuine latent product-test bug). Fixed both with `SHOW INDEXES YIELD type, state WHERE ...`. The integration compatibility run dropped from ~1m52s to ~22s as a result.
3. **`delete_message` id-format mismatch.** `IIdGenerator` stores ids as unhyphenated 32-char hex ("N" format), but the Python runner round-trips ids through `UUID()` and re-emits canonical dashed form, so `delete_message` looked up the dashed id, matched nothing, and returned `False`. Fixed by normalizing the incoming id to "N" format in the `delete_message` handler.
4. **`add_fact` request field is `obj`, not `object`.** The request DTO property was named `Object` (→ `"object"` under snake_case), so it never bound and the fact object arrived null, failing the Neo4j `MERGE`. Renamed the request property to `Obj`.
5. **`get_conversation` on an unknown session threw.** It returned the raw `session_id` as the envelope `id`, which the runner parses via `UUID()`; TCK session ids are not UUIDs (fixture: `f"tck-{uuid4()}"`), so this threw. Fixed to fall back to the nil UUID (`Guid.Empty`).

Also: `/setup` now returns `{"ok": true}` (matching the upstream C# reference conformance server) instead of `{"status":"ok"}`.

**Judgment calls now resolved** against the real upstream contract (`tck/adapters/base_adapter.py` Pydantic models + `docs/reference/bridge-protocol.adoc` + the `clients/csharp` reference server): `delete_message` `{"deleted": bool}` is CONFIRMED correct; `TckSessionInfo` field names were CORRECTED (`created_at` is required — the earlier "superset is safe" guess was wrong); `get_conversation` empty-envelope shape is CONFIRMED. This supersedes the "remain open"/"pending upstream confirmation" statements earlier in this Verification Log for those three shapes.
