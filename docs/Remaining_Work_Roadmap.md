# Agent Memory .NET — Final Prioritized Engineering Roadmap

_Post multi-agent review + upstream (neo4j-labs/agent-memory) recent-activity comparison. Window examined upstream: 2026-04-01 → 2026-06-05 (through v0.4.0). Source-of-truth doc: `docs/Memory_Review_and_Implementation_Plan.md`._

---

## 1. Executive Summary

The library is functionally feature-complete and the **primary recall path is correctly isolated** — vector recall for Fact/Entity/Preference filters by `owner_id` via `MemoryScope` (the reference pattern in `FactQueries.SearchByVector`), and per-application store routing exists via `IMemoryStoreContext` + `StoreDatabaseNaming`. However, R1/R1b multi-user isolation is **not actually complete**: a broad set of secondary read paths and the entire reasoning-trace and GraphRAG surfaces bypass owner scoping, and the API surface freezes at first NuGet publish, so these are genuine release blockers per the plan's own gate (`Memory_Review_and_Implementation_Plan.md:39,248`). The **single most important remaining gap** is that cross-user data leaks exist on multiple live and lookup paths — most critically GraphRAG (`Neo4jGraphRagContextSource` ignores `request.UserId` entirely) and all of ReasoningTrace (no `owner_id` persisted, read, searched, or scoped on session-delete), plus unscoped Fact/Entity/Preference lookups (by subject, triple, name, type, location, category) and a DI captive-singleton (`IMemoryStoreContext` registered Singleton but mutated per-scope) that can route a tenant to the wrong store. The **top upstream features worth porting** are fact/preference dedup-on-create (PR #97, small + high value, prevents node bloat) and the consolidation/memory-hygiene primitives (PR #113, the headline production-hygiene surface); medium-value graph-native adds are adopt-existing-graph, vector-index dimension validation, and `:TOUCHED` reasoning-audit edges. The bulk of upstream's other work (pluggable LLM/embedding providers, multi-tenancy, no-LLM pipelines, NAMS hosted backend) is already covered by the Microsoft.Extensions.AI stack and our `IMemoryStoreContext` model, or is SaaS-specific and skippable.

## 7. Recommended Next 3 Actions (sequenced)

1. **Close the reasoning-trace + GraphRAG isolation workstream (folds R2 into R1).** Do this first because it covers the only remaining _critical live-recall_ leaks and the API surface freezes at publish. Concretely: (a) persist/read `OwnerId` in `Neo4jReasoningTraceRepository.BuildTraceParameters`/`MapToTrace` and `ReasoningQueries.AddTrace/UpdateTrace`; (b) add `owner_id` filter to `ReasoningQueries.SearchByTaskVector` + a `MemoryScope` param to `SearchSimilarTracesAsync`, wire from `MemoryContextAssembler`; (c) scope `DeleteBySession`; (d) add `userId` to `IRetriever.SearchAsync` + all 4 retrievers and pass `request.UserId` in `Neo4jGraphRagContextSource`. (Ranks 1–4.) Add the matching integration tests (mirror `OwnerScopeIsolationIntegrationTests`).

2. **Fix the store-isolation correctness defects and prove them.** (a) Change default `IMemoryStoreContext` registration to **Scoped** (or add an async-context/thread-isolated wrapper) to kill the captive-singleton cross-tenant bleed; (b) make `StoreDatabaseNaming.Normalize` append `ShortHash(applicationId)` when Sanitize yields empty, eliminating the all-punctuation collision; (c) close the remaining unscoped non-vector reads in one pass by copying the `SearchByVector` owner pattern into `GetBySubject`, `FindByTriple`, `GetByName*`, `GetByType`, spatial searches, `GetByCategory`, and the `GetPageWithoutEmbedding*` backfill loop; (d) land the missing R1b/store integration + MAF-routing + `WithMemoryIdentity` + `StoreDatabaseNaming` edge-case tests (ranks 5–6, 7–13, 16–20). Then update README/`nextsteps.md` to reflect true isolation status and point to `Memory_Review_and_Implementation_Plan.md` (rank 15) — this is the documented NuGet release gate.
